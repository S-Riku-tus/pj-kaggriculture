# Round10再分析・公開研究拡張・Round11改訂方針

2026-09-24／研究版 revision 2。旧Round11依頼文を、この版で置き換える。

## 結論

B1を実績のある基準として保存しつつ、探索対象をB1への追加機能だけに制限しない。公開完成方策の再探索、B1の市場判断の改善、異系統相手への生産・更新計画という三つの研究を並行させる。新機能の追加だけでなく、置換・削除・無変更を比較候補に含める。

今回、前回の局所仮説を実際に追加対戦へ広げたところ、羊毛の価格ゲートを常時緩める版は悪化した。また、最終SELL並べ替えの狭い追加版は行動を一度も変えなかった。これは「修正を足せば次のブレイクスルーになる」と考えないための具体的な証拠である。

一方、未評価の完成方策、複数の相手軌跡を残す予測、相手の最終並べ替えを読む応答、価格床を区別する市場台帳が見つかった。完成方策の優劣はまだB1との同条件対戦で未確認であり、今回2500/3000到達を実証したわけではない。

## 2. B1の成功を、正確に引き継ぐ

前回の監査済み公開記録では、B1は71戦40勝28敗3分、最高2392.3337、取得時点2158.5876。序盤18連勝、最後20戦9勝10敗1分。相手2000未満には15勝0敗、2200以上には5勝14敗3分で、2500以上との対戦はない。

同条件の保存ローカル比較でもv124からB1への改善があり、これは実績のある新しい基準である。ただし、新規rankerの学習による上積みではなく、公開herd-safeの強い実行方策を取得・選定・導入できたことが中心だった。学習版のfresh24試合はB1と全行動・観測まで一致し、1344推論に対して選択0・変更0だった。

したがって、再現したい成功手順は「現実に強い方策を発見し、自分の条件で検証すること」である。B1のコードを必ず土台にすることや、すべてを学習にすることは、その手順の必須条件ではない。

## 3. 新しい128対戦：前回の局所改善を、そのまま常時化してはいけない

### 3.1 比較設計

4方式×4相手×4seed×両seat＝128試合。1方式32試合、独立な環境seedは4本である。相手はB1、添付のV57、Order Book、Metav4で、共通の祖先を持つ公開方策群である。4つの完全独立した未知戦略群とは扱わない。

- B1：変更なし。
- wool_gate_open：`V9_RACEGATE_BASE['WOOL']=0`。他の条件は変更しない。前回の1判断だけの介入ではなく、全判断でこの基準を変更する診断版。
- final_response：最終注文が2～6本のSELLだけの場合に、相手も自分の最終並べ替え後の注文列を使うと仮定し、順番を再探索する。数量・農作業・非SELL注文は変更しない。Order Book v3を参考に今回独立に作った限定実験であり、原作者v3の完全再現ではない。
- combined：上記二変更の組合せ。

|---|---:|---:|---:|---:|---:|

全128試合が719判断で終了し、例外0・注文上限超過0だった。各リプレイの圧縮バイトhashと終局結果を保存した。最大観測callback時間は約0.858秒だが、並列実行・別ハードウェア・別ローダーでの測定なのでKaggleの時間制限通過保証には使わない。

### 3.2 どの勝敗が変わったか

常時緩和はB1比で、元の勝ち6試合を敗戦へ変えた。元の敗戦からの救済は0。引き分け8試合は4勝4敗になった。平均得点率差は−18.75ポイントである。B1以外の相手だけなら20勝4敗から14勝10敗になった。

Order Bookに対して8勝0敗から4勝4敗、V57には6勝2敗から4勝4敗。弱い相手へ大差で勝つことでは埋められない悪化である。

ただし4seedという小標本であり、これを全母集団での真の効果−18.75ポイントと推定し切ったわけではない。今回の無条件版を採用する根拠がないこと、相手依存の条件付けが必要であることを示す。

### 3.3 「市場しか変えていない」は、実際の農作業不変を意味しない

常時緩和は32対応試合で830判断を変え、農作業命令にも計120ターンの違いが生まれた。農作業のソースを直接改変していなくても、価格・在庫が変われば既存の給餌判断等が反応する。

例：seed402609243対B1、decision590。基準版は羊毛価格37でactor2にFEED、変更版は価格11でPASSだった。その後632、652にも給餌差分が生じた。したがって、単一判断・後続固定の局所評価だけで長期効果を保証できない。詳細は`evidence/gate_indirect_field_changes_example.json`。

### 3.4 最終並べ替えは、今回の狭い候補では効果0

final_responseは342判断を評価対象とし、582個の代替順を採点したが、採用0だった。32試合すべてで全観測・双方行動・終端状態がB1と一致した。combinedでも追加の応答変更は0だった。

よって、この実験は「Order Book v3全体が無価値」とは示していない。原作者版は固定価格注文を含む配置も扱い、今回のSELL-only版とは候補集合が異なる。示したのは、B1上でこの狭い探索を再実装しても新しい有利な行動を作れなかった、ということである。

組合せの相互作用が0だったのも、片方が非発火だったためである。両機能が実際に動く組合せの加算性・相互作用は未検証とする。

### 3.5 前回の＋837と矛盾しない

前回は実戦112748339のdecision567一度だけ変更し、その後3遷移の行動を固定した。自分＋286、相手−551、margin＋837はその局所条件の結果である。今回は異なる初期条件から、常時の変更に両者が反応した。両実験が答えている問いは異なる。

前回の局所的に有利な1状態は、条件付き方策の教師候補として保持する。今回の常時緩和で悪化した状態も負例として保持する。どちらかを捨てて一方の結論だけに合わせない。

## 4. B1に既にある機能と、実戦から見える残余

本体の最終経路は概ね`_cxd_agent → e410_agent → e402_agent → rescue_agent → opening_liquidity_agent`。EarlyCycle、先行売却予約、相手推定、入力材の保護、施肥抑制、終盤種予算、最終搬入、注文並べ替えを既に持つ。

新しいNotebookに同名の機能があっても、「B1にない新機能」とは限らない。関数の存在、実際に呼ばれる経路、設定、発火、最終行動差分まで調べる。

### 4.1 終盤の売れ残り一掃を、次の大改善と決めつけない

71実戦のraw終端で、売買対象商品の倉庫在庫と全作業者の手荷物はいずれも合計0だった。decision672以降のBUY_SEED要求も0だった。種の残りは63試合で存在するが、全71戦の額面種代の合計2050、平均28.8732である。これは過去の購入原価であり、売却可能な資産価値でも、削減すると同額儲かる因果効果でもない。

HIRE・BUY_LAND・BUY_SEED・BUY_ANIMALの正の要求についても、保存された実約定表では部分約定／未約定0だった。したがって、現B1の71戦に「終盤に数千の種を無駄買いする」「固定価格購入が頻繁に資金不足になる」という大穴は観測されていない。

終端在庫0は途中の廃棄0や、最適な終盤計画の証明ではない。ただし、公開資料の別の弱い版にあった終盤浪費を、B1にもあると決めつけて修正するべきではない。

### 4.2 4区画目を一律禁止しない

B1は19/71戦で4区画を使う。トマトを植えたのは12戦で、初植えは全てd18。残り7戦には羊を大きく増やした農場がある。4区画なのにトマトがないことは、土地が未使用という意味ではない。

「過去Top3が3区画だった」という記述は、現在B1に対する無条件の安全制約にしない。土地・雇用・配置・餌・収穫・現金化まで含む計画の利益と勝敗を比較する。

## 5. 市場修正では解消できない具体例：112752873

この試合はB1が132294、相手136064で3770負けた。農作業命令の一致は3/719で、同型市場戦とは異なる。

| 指標 | B1 | 相手 |
|---|---:|---:|
| イチゴ販売量 | 249 | 376 |
| イチゴ売上 | 54334 | 81659 |
| イチゴ平均実売価格 | 218.2088 | 217.1782 |
| 全品目の販売売上 | 157086 | 161815 |
| 雇用支出 | 3897 | 6960 |

B1はイチゴを少し高い平均価格で売っている。それでも数量が127少なく、イチゴ売上で27325負けた。一方でB1は牛乳・羊毛・肥料・メロン等で取り返しており、27325をそのまま「簡単に回収可能な改善幅」としてはいけない。

全売上差は−4729、支出全体ではB1が959少ないため、終局差が−3770となる。相手の雇用費は3063高い。労働を減らすことだけが正解ではなく、追加労働を何の売上へ変えたかが重要である。

この相手はd2に最初のイチゴを植え、B1はd5。d15ではイチゴ48株に対してB1は33株。d12の資金はB1が7568多かったが、終局で逆転した。途中現金が多いだけで「勝つ経済を作れた」と判定しない。

今回の全71戦でも、B1のイチゴ初植えは全てd5である。これは資金・移動・給餌・配置を伴う一貫した経路の性質であり、作付日の定数だけをd2に変える修正では解決しない。早期投資から回収まで通る別の完成経路を、候補として取得・作成して評価する必要がある。

この試合の相手の実装は未取得であり、保存行動を変化した状態へ貼り続けるものを「本物の反応する相手」と呼ばない。

## 6. 公開研究から見つかった、次の具体的な候補

出典URL・版・確認範囲は`SOURCE_MAP_JA.md`、機械可読版は`SOURCE_REGISTRY.json`。以下の作者数値は今回こちらで再実行したものではない。

### 6.1 完成方策そのものを比較する

Round10の取得一覧は7候補だった。今回見つかったMore Wheat、Order Book v3、Moon、v15stack、Wonderful、Master Hybrid等は、B1に機能を足す前に、取得できた正確な原版をそのまま比較する対象になる。

ただし、同じ祖先・同じ行動本体の別タイトルが多い。v15stackのscriptとnotebookを別候補に数えない。Wonderfulの説明抽出ファイルが空だったため、この資料だけで内部の強さを断定しない。掲載レート、歴代最高、作者のローカル得点率を混同しない。

全体置換候補がB1を上回るならそれを採用候補にしてよい。必ずB1へ移植し直す必要はない。逆に弱い原版でも、相手モデル・資材計算・輸送計画の一部分を研究材料にできる。

### 6.2 相手が並べ替えた後の注文に応答する［S04］

B1の`_CXD_MODELS`は既定で空であり、実際には自分の並べ替え前の注文を相手の代理にする。相手もOrder Book系で最終並べ替えをするなら、その仮定はずれる。

Order Book v3は、相手の最終並べ替え後を仮定して一段応答する。原作者の24seed・両seatで、元Order Bookへの48戦は29勝3敗16分だった。ただしPipe18/V56への勝敗は対照と変わらず、平均marginは12.21悪化したという限界も公開している。

次は今回のSELL-onlyより広い候補を、資金・在庫制約を守って試す。ただし、コピー先の`_CXD_HOST`から呼び出すとB1の外側にあるE410/E402/rescueを飛ばす危険がある。B1の最終entryを一度だけ呼ぶ構成を保ち、旧・新・両仮説への頑健版を比較する。

### 6.3 似た相手の可能性を一つに決めない［S03］

More Wheatは、最上位の履歴に近い3本までを残し、そのいずれかが近い売却を予測する場合に予定販売を早める。作業後の実在庫を確認し、販売計画の範囲で動く。原作者は55試合、25対応比較で5改善0悪化を報告する一方、相手系統が狭いことや早売りの誤判定を明記している。

B1では「農場が同じ」ことから「市場の注文も同じ」と早く決めない。時刻・数量・順序に異なる複数仮説を置く。3本のどれかが売るだけで全在庫を即売りするような無条件化は避け、誤った先売りの損失も比較する。

### 6.4 最終的に返す注文列で最適化・記録する［S05］

Moonは先売りや空slot処理後に、最終SELLブロックを並べ替える。原作者は1008対戦の三方式・7相手・24seed・両seatを公開している。ただし前身bc80との差の95%seed区間が0に接し、公式スコアはその実験からは確立していない。

B1に同じ改善余地があるかは別である。後段で本当にSELLの数量・配置が変わるかを計測し、既に最終段に相当する最適化があるなら重ねない。今回の無変更32試合はこの点の警告になる。

### 6.5 価格床では「分からない」を保つ［S06］

価格1で売れても市場在庫が増えない例外がある。買戻し不能な7品目について、I＝現在市場在庫、J＝次観測、C＝既知の町消費、S＝自分の実売量と置くと、D＝J−I＋Cは両者の在庫増分であり、相手実売量の下限はmax(0,D−S)となる。`price(J+C)>1`なら相手売却量をD−Sと確定できる。次の表示価格だけでなく、町消費前の価格を見る。

今回これを71実戦に適用した結果：

| 検査 | 件数 |
|---|---:|
| 全品目ターン | 357343 |
| 確定条件成立 | 345221 |
| 確定条件不成立 | 12122 |
| 相手実売イベント | 9931 |
| 相手が売ったが市場増分Dが0 | 530 |
| 次表示価格は1超だが町消費前は床 | 1421 |
| 下限違反／確定値不一致 | 0／0 |

自分の実売量と相手の正解数量には、前回検算済みの実約定表を使用した。相手の正解はオフライン評価専用であり、提出方策の入力にはしない。市場台帳自体の入力は公開在庫・出現済み店・自分の最終実行注文から構成する。

530件を「相手は売らなかった」という0ラベルにすると誤る。逆に、12122行全てに売却があったとも言えない。不確定として上下限・確信度を保つ。自分の最終注文・DROP後在庫を誤って記録すれば、価格床処理だけ正しくても誤推定になる。

原作者は正しい自売却記録へ直した560対戦で、方策としては悪化した結果も公開している。したがって台帳はまずshadow診断へ入れ、予測器を再校正してから意思決定へ接続する。正しい記録と強い方策を同一視しない。

## 7. 次の開発を三つに分ける

### Track A：公開完成方策の探索と比較

B1以外の選択肢を本当に増やす。新しい候補の原版を保存し、同じ相手・seed・seatで比較する。名前ではなく、実行hash、農作業列、市場応答、対戦相性で重複を扱う。各候補を最初からB1へ移植しない。

### Track B：B1上の小さな市場改良

条件付き羊毛売却、相手の最終注文への応答、複数仮説、最終台帳を別armにする。特に今回の無条件ゲート版と無変更の限定SELL版を負の／無効果の対照として残す。2×2比較は両変更が発火したかを含めて解釈する。

### Track C：実戦の異系統相手に向けた完成生産計画

早いイチゴ投資、品目別・時期別の更新、家畜から作物への転用、需要に見合う雇用、既存区画でのトマト等を、資材・位置・輸送・売却まで含む計画にする。B1の前半経路に、未来の状態を前提とした別の後半だけを貼らない。状態不一致なら、遷移を完了する計画を作るか切替しない。

Track Aの良い完成方策がTrack Cの材料になる。Track Bの改良を新しい土台へ移すときも効果は再検証する。移植前に効いたことは移植後の保証ではない。

## 8. 学習の役割を更新する

Round10 rankerは72件・12相手×seed groupに限られ、test18件中positive1。訓練損失低下に対して検証損失が悪化し、test accuracy88.89%は常時negativeの94.44%を下回る。これにepochを足すだけでは今回の新しい候補を作れない。

まず、正しい候補が実際に行動を変えられることを確認する。自分が訪れる局面で、KEEP_B1、条件付き売却、別順序、状態互換な完成計画を比較し、終局まで進めた結果から変更価値を学ぶ。正しい実行でも不利な例、実行不成立の例、単なる同値候補を分ける。

予測課題なら、相手の要求数量ではなく実約定・価格へ影響した数量・注文順を区別する。現在の決定に必要な1～4ターンと長期の24ターンを混ぜずに測る。分類精度だけでなく、予測によってどの選択が変わり、勝敗をどう変えたかを確認する。

学習ありを必須の採用条件にもしないし、過去に弱かったから学習全体を禁じることもしない。原版・ルール・学習・無変更を同じ候補集合と実行器で比較する。

## 9. 評価と締切

主指標は勝ち1・分0.5の得点差。勝→負、負→勝、分→勝／負を明示する。平均margin、自資金、相手資金は原因理解と探索用で、単独で採用を決めない。

同じseedでも盤面の空き方が変われば乱数消費と後の店舗列が変わり得る。同seed比較は通常環境での全効果比較として有効だが、常に同一店舗列の比較だとは言わない。店舗固定は診断専用とする。今回の128対戦では対応する店舗列が一致したが、今後の生産変更にも適用できる保証ではない。

新規候補を何十も試した開発集合を最終holdoutへ再利用しない。共通seedでクラスタ化した不確実性を示し、相手の祖先が共通である限界を記録する。「1敗も新しく作らない」だけを絶対条件にして改善候補を永遠に棄却するのではなく、事前に決めた得点改善・重要相手の許容悪化・実行品質で判断する。

公式Timelineの最終提出日は2026年9月30日［S02］。日付は確認した公式記載であり、メダル条件をレート2500/3000と断定する根拠ではない。残る期間は、新しい巨大基盤だけに使い切らず、完成方策の探索と小規模な因果比較を実際の候補作成へ結びつける。
