# v124→v125 分析パッケージ

## 読む順序

`REPORT_JA.md`が詳細分析、`CODEX_V125_PROMPT_JA.md`がリポジトリを開いたCursor/Codexへ渡す入力文である。どちらもv125を実装・提出済みという意味ではない。

`tables/`には数値の根拠を保存した。最初に読む表は、`performance_summary.csv`、`v124_rating_bands.csv`、`price_floor_sales.csv`、`behavior_summary.csv`、`crop_first_plant_day.csv`である。

`forensic_cases.json`は、v124のCAREボーナス順序、Top2の羊退出→麦、v124の追加トマト分岐の実例を含む。`v124_same_game_net_cash_decomposition.csv`は同じ試合の相手に対する現金差を再構成した表である。

## 重要なデータの定義

- dayは0始まり。step0は初期状態、step1～719は行動後の記録状態。
- 勝率はPUBLICだけ。VALIDATIONは除外。
- target_submission / sidは、どちらの提出視点の集計かを示す。同じepisode_idが上位双方の行に現れることがある。独立試合数を数えるときはepisode_idで重複除去する。
- `op_*`は出力された命令数。`verified_*_ok`は独立一歩監査で前提条件を満たした命令数。経済的に有益だったことまでは意味しない。
- `actual_*_cash/qty`は監査で再構成した実行注文の現金・数量。注文要求数量とは異なる。
- `flows_reconciled`は対象側の現金遷移を監査できた行。Top3 episode111036541の120差を除き、最終現金帳簿が一致した。
- `floor_unit_share`は、販売した総数量のうち、単位売却価格が1だった数量の比率。複数価格を含む注文も単位ごとに数える。
- `observed_crop_cohorts.csv`は日境界または終局に観測された作物の植付世代。植えた当日に失敗して境界まで残らなかった作物は含まれない。前作は日次観測から推定する。
- `retirement_tile_reuse.csv`は個体退出と、その後の日次観測で同じタイルが作物になった記録。意図や最適性は断定しない。
- `inferred_demand_daily.csv`の値は、記録された市場在庫と実行注文から再構成した、その日の店構成が続いた場合の日消費率。予測未来ではなく事後解析であり、4つの市場在庫不一致遷移には監査の制約がある。
- `economic_daily_metrics.csv`は日ごとの実行命令・収量・市場現金。廃棄の品目内訳は元の処理順近似が残る。補正済みの廃棄総量・品目内訳は`all_public_episode_metrics.csv`の`overflow_*`を参照する。日別品目廃棄を厳密に使う際は生の不一致記録を合わせて検証する。

## 監査の限界

監査は各ステップで記録された直前の状態に再同期する。未知の候補を終局まで回す完全互換シミュレータではない。

725,471遷移で、市場在庫4件、現金4件、倉庫内訳968件の不一致を確認した。倉庫の容量超過時の品目順序が重要で、各品目の内訳は観測された次状態を使って事後補正している。対象側収支で不一致が残る1件は価格・収益の集計から除外した。`audit_and_provenance.json`と`audit_raw_mismatches.json`を必ず参照する。

提示する統計は観察結果であり、候補方策への変更の因果効果ではない。上位とv124では相手・町・試合時期が違う。記録された相手行動を固定して再生する試験も、相手が変化に反応する実戦と同一ではない。

## 再集計

Python 3.10以上で、同梱スクリプトはこの5提出のログを再集計する。元の大きなZIP5本はこのパッケージに再同梱していない。小さいメタデータZIP3本も入力ディレクトリに置いてよい。

```bash
python -m pip install -r scripts/requirements.txt
python -m unittest discover -s scripts -p "test_*.py" -v
python scripts/reproduce.py --input-dir /path/to/original_zips --output-dir /path/to/analysis_work --workers 4
```

Windowsでは適切なパスを指定する。解析はZIPから直接読むが、各ワーカーがリプレイをメモリに展開する。メモリが小さい環境では`--workers 1`を使用する。元ZIPを全解凍する必要はない。解析キャッシュ・中間CSVを書き込める空き容量を確保する。

スクリプトはネットワークへ接続しない。v125本体を実行・提出しない。途中で失敗した場合はoutputディレクトリの各段階の`.log`を確認する。圧縮キャッシュの書き込み中に中断した場合は、該当の不完全な`.json.gz`を削除して再実行する。

入力探索はファイル名の`submission_<ID>`とリプレイJSONを含むZIPで判定する。レポートのラベル・ケース抽出は今回の5提出用である。新しいv125提出を分析する際は、ラベル辞書・比較群・代表ケースを変更する必要がある。

同梱の単体テスト5件は監査実装の内部整合性を確認するもので、公式エンジンとの完全同一性を保証するテストではない。ポータブル化したスクリプトの構文確認と単体テストは実施した。元の分析は同じ分析ロジックを用いた作業環境で完了しているが、最終パッケージの全段階を最初から再実行したわけではない。

## 使い方の注意

今回のログはすべて分析済みで、最終的な未使用holdoutではない。学習・候補選択・評価を混同しない。相手private、隠れseed、未来価格、最終結果、観測にない提出ID/レートを意思決定特徴量へ流用しない。

公式仕様・公開コード・Kaggle参考ページの参照先と取得できなかった範囲はREPORT_JA.mdの末尾に記載した。可変masterではなく、実際に評価に使うエンジンのハッシュを固定する。
