## Phase 1：ルールと情報境界を固定する

次のテストを、実際に採用するエンジンへ当てる。

- 行動tは観測t-1を受けて出力され、結果が観測tに入る。初期0～最終719。
- ユニット行動→市場→町消費→所定の日次更新の順。
- 同じターンの種購入・雇用を、先行するユニット行動で利用しない。
- 同一作物のPLANT要求数がその時点の種数を超えると、その作物の要求が全取消になる。
- 同一市場スロットでの同一商品の同時販売を、座席0の一括先売りとして近似しない。
- 倉庫容量、DROPと数量指定PLACE、日末の手持ち流入と廃棄を一致させる。
- 日次家畜処理のCARE順序：既存pendingボーナスの生産への払い出しの後、当日のCAREが次のpendingへ加わる。
- 実測のCAREテスト：episode110837769、(4,3)、191→192でyield0/pending5/fed/cared trueから、yield6/pending1になる。
- 最終day29の次の日次生産を計上しない。予定生産を越えたCARE残高に価値を付けない。
- 店の重複は個数として扱う。

観測にない情報を推論時の特徴量へ入れない。禁止する入力は、相手のprivate、将来の店、リプレイinfo.seed、将来価格、勝敗・最終現金、提出ID・相手レートなど観測に存在しないメタデータである。これらは分析・分割・教師ラベルに用途を限定する。教師の行動を学ぶときのその教師自身のprivateと、対戦相手のprivateを混同しない。

## Phase 2：基礎経済計画を置き換える

まずTop1/2型の、早期イチゴ・3区画・輪作まで成立する一貫した計画を候補Aとして実装する。初期の2牛3羊は仮説・参考形であり、頭数だけ固定コピーして他の作業を旧手順のままにしない。種代、家畜代、メロン・麦・羊毛等の入金、土地費、雇用、PICKUP、水やり、収穫、出荷を同じ計画で解く。

候補BとしてTop3型のより多い羊・ガチョウ等を含む計画を扱う場合は、別の完成計画にする。3提出の平均頭数を混ぜた架空の計画は作らない。

既存v124の4区画目トマト分岐は比較候補として残す。3区画内の輪作との比較ができるようにする。記録上のトマトの植付日はd18で固定だが、上位のd11～12からの分岐も実行可能にすることを狙う。

個別の元リプレイに沿った行動再生は実装の確認に使えるが、新しい条件での自律的な強さを証明したと書いてはいけない。元と資金・種・在庫・土地・作物年齢・位置・雇用が異なる状態に、途中の固定手順を接合しない。

## Phase 3：少数の意味のある適応を加える

### 資産台帳

各タイル・家畜について、次の生産、終局までの有効生産、収穫待ち、肥効期限、pending CARE、維持費、手間、後作候補を追跡する。日末倉庫流入を見積もる。現在の頭数だけのルーターから脱する。

### 維持モード

通常維持、省力維持、計画的退出を比較する。現在価格だけで逃がさない。未収穫品・肥料・次回生産・既存CARE残高・餌価格・作業者・後作の成熟期限を含める。

### 長期評価と局所実行

経済価値は終局まで評価し、経路と作業者割当は短い時間範囲で精密化する。相手の公開農場・過去の公開市場変化から将来供給を予測し、複数シナリオで候補を評価する。将来の真の対戦ログをオンライン予測の代わりに入れない。

比較候補例：現在計画の継続、羊の維持縮小→麦、牛の維持縮小→ニンジン、麦・メロン跡地→トマト、イチゴ跡地→短期作物、4区画目トマト。これらの組み合わせ数を無制限に増やす前に、実行可能性と誤差を計測する。

### 施肥

追加収量だけでなく、肥料の売却機会、PICKUP・輸送、作業順、収量上限、収穫期限、販売価格の低下を含めて評価する。麦の施肥を重点候補にするが、「65回以上」など回数を成功指標にしない。

### 市場・輸送

出荷量からの価格変化と相手供給を含め、供給過剰な生産を抑える。既にある終盤在庫の価格1売却は許可する。容量超過の前に出荷・数量指定PLACE・回収の分散を検討する。すでに捨てた品物に架空の高額価格を掛けて改善額を計上しない。

## Phase 4：比較実験

最低限、次の独立差分を用意する。

- 現行v124（凍結）。
- v124に実行品質の修正だけを入れた版。
- 新しい一貫した基礎経済計画だけの版。
- 新しい基礎計画に供給予測・退出転用・施肥配分の適応を加えた版。

まず実行品質、その後基礎計画、その後適応の順に寄与を分解する。高い平均現金、少ないPASS、家畜消失ゼロだけでは採用しない。

同じ相手・seed・座席で基準と候補を評価し、先後を入れ替える。主指標は勝率と相手系統別の成績。平均差、中央値、下側の差額、廃棄、価格下限販売、発動率、予測誤差、時間制限を補助指標にする。系列相関を考慮し、信頼区間を過度に狭くしない。

旧自作エージェントは回帰検出に使えるが、それだけで大会の2000・3000級と判定しない。上位コードが取得できなければ存在するふりをしない。固定相手行動の再生は相手の反応がない限定検証と明記する。必要な代理相手は公開ルール・許された資料で構築し、その代理との勝率を実レートへ直接換算しない。

今回の全添付ログは分析済みであり、最終未使用holdoutではない。候補と判定基準を固定した後で、新しいseed・未使用系統・新しい対戦を最終確認に使う。提出IDだけを分けても同系列の方策が漏れる可能性に注意する。
