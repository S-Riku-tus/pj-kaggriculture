## D. 最優先で修正する実行時入力の欠陥

### D1. 自分の途中注文を相手の売却と誤認している

`_v92_p_update` は `_V9_RACE[player]["prev"]["own"]` を用いて、

```
rival_estimate = inventory_delta + town_draw - recorded_own_sale
```

を計算している。しかしこのownが記録されるのは最終entrypointから返す前であり、外側のラッパーが注文を増減・変更する。

固定回帰ケース：
```
M20 vs v57 / seed612609264 / seat0 / step645
最終市場注文:
  SELL STRAWBERRY 13
  SELL WOOL 7
  BUY_SEED CARROT 1
相手市場注文:
  BUY_SEED CARROT 1
```

WOOLは台帳own0・実own7・実opponent0なのに推定opponent7。STRAWBERRYは台帳own0・実own13・実opponent0なのに推定opponent13。

これを修正する。最終行動より後段で改めて台帳を確定し、次観測との整合で検証する。単に最終注文の要求数量を足すだけでは足りない。行動順、同じターンの倉庫搬入、重複注文、在庫不足、後段の削除・並べ替え、実約定数量を扱うこと。

現在の倉庫在庫が0だからSELL無効と決めつけない。農作業が市場より先に実行され、同ターンに搬入される場合がある。自分のpost-field状態の計算を純粋関数として検証する。候補比較のために本体を同じターンで複数回呼び、内部状態を二重更新してはいけない。

### D2. 売却中の価格下限到達を扱えていない

固定回帰ケース：
```

自分の実売却12、相手の実売却12
```

固定公式ソースでは価格下限でのSELLは市場在庫を追加増加させない。前の観測価格が3以下ならskipする現行条件では、「開始価格は高いが注文の途中で下限に達した」事象を取り逃す。

Research RevisionのS06/market reconstructionの知見を、実行時入力へ接続する。全部を正確な点数量で識別できると仮定しない。少なくとも `exact / lower_bound / interval / censored / unknown` 等の信頼区分を持ち、観測できない0と本当に売却なしの0を分ける。

相手の非公開在庫・内部状態・未来行動は提出時の特徴に使用しない。シミュレータの真値は、入力台帳のテストと学習ラベル生成の評価用だけに使う。公開観測と自分の最終行動から得られる区間を学習器へ渡す。

## F. 市場判断の作り直し

M20は候補軌跡を増やしたが、最有力が売却を予測しなくても次点1本の予測だけで前倒し売却する。候補数を増やすことを校正済みの不確実性処理と呼ばない。

Dの入力を修正した上で、WAITを含む候補の価値を比較する。候補は数量・注文位置・待機時間を区別する。注文数上限やHIRE/BUY_LAND等との関係も含める。

最低限、次を検討・実装・計測する。

1. 候補軌跡の重複・近縁性を調べ、同じ予測のコピーを独立票として数えない。
2. 正確な数量が見えるイベントと下限による打切りイベントでスコア更新を分ける。数量・時刻の校正を検証する。
3. 街の次回消費、相手の売却、在庫保持、将来の自分の搬入、価格への影響を含め、今売る場合と待つ場合を比較する。
4. 短期marginだけでなく終局得点と自資金・相手資金を分解する。平均marginが改善しても得点が下がる例が今回存在する。
5. 相手がこちらの市場操作に反応するケースを測る。固定された相手注文の再生だけで採用しない。

売却の候補価値は、概念的には次である。

```
DeltaScore(s,a) = E[終局得点 | 現在状態s,候補a] - E[終局得点 | s,B1最終行動]
DeltaMargin(s,a), DeltaSelfCash(s,a), downside risk も別に保存
```

期待値の重みを確率と呼ぶなら、その校正を示すこと。単に多数決を確率へ言い換えない。情報不足ではB1へ戻る選択肢を残すが、全てB1へ戻って終わった場合は「候補を学習したが使わない」でなく、どの条件が選択を阻んだかを報告する。

市場だけの局所修正で今回全作業を終わらせない。次の生産経路を必ず独立した作業対象とする。

## G. 別生産経路を最低1本、完遂可能な形で実装する

Round11で6つの公開完成版を実行したことは成果だが、主要な生産経路はB1と同様であり、別戦略の探索としては足りない。

前回資料のepisode112752873の対戦相手はSTRAWBERRY初植えday2・day15に48株、B1はday5・33株。資料の集計ではSTRAWBERRY売却数量376対249、売上81659対54334、平均単価217.18対218.21、雇用費6960対3897であった。これは参考となる観測例であり、その相手の実装を入手・再現したという意味ではない。

公開完成ソースの追加探索は行ってよい。ただし、同系統の名前違いを再発見し続けたり、相手のコードが見つからないことを理由に生産経路を未実装のまま終えたりしない。入手できなければ、同様の機会を狙う独自の実行可能な経路を実装する。

初期資金3000からどの収益を先に作るか、土地をいつ解放するか、何を減らしてSTRAWBERRYへ投資するか、必要な種・人員・位置・水やり・収穫・搬入を全てつなぐ。人員は日替わりであり、雇用費は人数に対して増える。播種日だけを変えて古い行動列へ戻すパッチは禁止する。

次の形を候補として比較する。必ずしも全てを完成させる必要はないが、少なくともB1と異なる1本を終局まで完走させること。

- 初期収益から継続収穫作物へ早く投資する経路。
- 家畜への投資・継続飼育・作物への転換を、残日数と価格環境に応じて変える経路。
- 街の消費・価格の持続性に合わせ、TOMATO/STRAWBERRY等の構成を変える経路。

最初から全体最適と称する巨大な探索器を作らず、観測可能な開始条件、資源制約、各日の維持義務を持つ完全な小経路を作る。B1へ復帰するなら、位置・在庫・作物・家畜・土地・雇用・予約状態について復帰条件を検証する。条件が合わない場合はその経路のcontrollerで最後まで進める。

指標：初植え日、各日の作物/家畜数、実収穫量、実売却量、品目別売上、種・土地・家畜・雇用等の支出、維持義務の失敗、遊休作業、搬入失敗、終局資金、対戦得点。48株を達成しただけで合格としない。追加売上を追加利益と混同しない。

生産と市場の組合せは、少なくとも2×2で主効果を分離する。

```
P0M0 = B1生産 + B1市場
P0M1 = B1生産 + 改善市場
P1M0 = 新生産 + B1相当市場
P1M1 = 新生産 + 改善市場
```

「B1相当市場」はB1の古い経路にしか成立しない未来予定売却をそのまま使う意味ではない。新生産の将来供給に適合させ、どの部分を共通化し、どこを経路依存にしたか説明すること。

## H. 学習を接続する条件と実施内容

「ルール候補が落ちたから今後も学習は全て不要」としない。一方、旧分類器へepochを追加するだけにも戻らない。

まず合法で実行可能、かつ最終行動を変える候補を作り、現在状態からの反応型分岐でラベルを作る。分岐時は双方の内部状態・乱数状態を正しく復元する。複製機能がない場合は同じprefixを再実行して状態を構築する。相手は分岐後も反応させる。

ラベルには、候補の可否、最終行動の差、実約定・生産差、短期価値、終局自資金差・相手資金差・得点差・破綻を持たせる。実行時入力と未来を使った教師ラベルを厳密に分ける。

診断用oracleで候補集合の上限を測る。oracleでも改善しないなら、候補生成や実行計画を作り直す。oracleが改善するのに学習選択器が届かないなら、データの網羅性・特徴・モデル・校正・選択条件を改善する。oracleは未来を見た上限であり、提出可能な性能と呼ばない。

有効な候補集合ができた場合は、小さな価値推定器または候補rankerを実際に学習し、重み保存・再load・新規推論・最終選択まで通す。報告するのはaccuracyだけではなく、常時B1対照、oracle、ルール選択器、学習選択器の最終得点差である。

分割はepisode/seed/source-family単位とし、同一試合の近接ターンをランダム分割して独立testと称しない。全ての選択がB1になる場合は、そのモデルを提出改善と呼ばない。モデルが不採用でも、生産候補・市場候補・counterfactual dataset・評価結果は成果物として残す。

## I. 評価と採用

Round11のseed612609241〜612609264、および最初の4診断ケースは全て開発データになった。再度「未使用holdout」と呼ばない。既知の6つの転落seedだけにルールを合わせない。seed値や相手IDを提出方策の条件分岐に使用しない。

診断パネル、候補選択パネル、最終の新規holdoutを分ける。新規seedは候補・ハッシュ・ゲートを固定後に生成する。可能なら生産系統が異なる反応型相手を含める。自作v122〜v124は同一/近縁性を確認して1系統として扱い、他に新生産経路、相手のmarket応答の強弱等を加える。弱い相手で勝率を水増ししない。

主要指標はwin1/tie0.5/loss0。相手別差、seed clusterの区間、自資金、相手資金、margin、重大破綻、W→L、L→Wを併記する。W→Lはabsolute件数だけでなく分母・seed重複も明記する。

Round11の「W→Lが2件以下」等を結果を見て緩めない。今後のサンプルサイズに合う新基準を使う場合は、最初に別実験として理由と閾値を固定する。得点増・十分な不確実性評価・相手別の非劣化条件を含める。今回の2票条件も旧基準を通ったことにしない。

公式PythonとC++のparityは、修正による分岐が実際に起きたケースを含めて確認する。全てB1に戻るケースだけのparityでは不足である。719意思決定に加え、終局観測・DONE/DONE・終局資金を保存する。

実ローダーは、変数名 `agent` を直接呼ぶものではない。公式 `get_last_callable` の空のexec名前空間と最後のcallable選択を使って、同梱ファイル・import・__file__不在・エピソードリセット・両seat独立ロードを確認する。診断関数が最後のcallableにならないようにする。モデルや埋込ファイルのpathも実環境で検証する。
